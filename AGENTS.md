# AGENTS.md — инструкция для агентов

Проект: **«Лавка на перекрёстке миров»** — уютная браузерная игра (хозяин волшебной
лавки: головоломки, обустройство, найм команды, автобои рыцаря). Весь код на русском,
все пользовательские тексты СТРОГО по-русски. Дизайн-документ: `Второй анализ после
ответов.txt` в корне. План/история: `PLAN.md`, `game/README.md` (местами устарели —
истина в коде и тестах).

## Стек и запуск

- Чистый JavaScript (ES-модули) + Canvas 2D + DOM. **Ноль зависимостей в продакшене**;
  esbuild — только чтобы собрать `game/bundle.js`.
- Запуск игры: двойной клик `game/index.html` (работает с file://) или
  `npm run serve` в `game/`.
- **Команды (cwd = `game/`):**
  - `npm run build` — собрать бандл. **ОБЯЗАТЕЛЬНО после любой правки `src/`**:
    игра грузит `bundle.js`, не исходники.
  - `npm test` — `node --test "tests/*.test.mjs"`. После правок всегда
    `npm run build && npm test`.
  - `node tools/sim-world.mjs <worldId> 40` — баланс мира (винрейт эндгейм-билдом).
    Миры: nm, sw, sf, ash, cr, jade, deep, mist.
- CI (GitHub Actions, `.github/workflows/deploy.yml`): пуш в main → тесты → сборка →
  деплой на GitHub Pages (https://k8rvin.github.io/CozyAdventures/). Node 22
  (test-runner с glob не работает на Node 20 — не понижать).

## Структура

```
game/
  index.html, styles.css, bundle.js (собранный), manifest.webmanifest, sw.js (PWA/офлайн)
  src/core/   — чистая логика БЕЗ DOM (state.js, formBattle.js, *Puzzle.js, items.js, rng.js)
  src/data/   — контент как данные (items, enemies, battles, puzzles*, crew, shop, sets…)
  src/ui/     — экраны (app.js — роутер и ctx; hub.js — сцены-хабы; *View.js);
                cursors.js — тематические курсоры: роутер ставит body[data-cursor],
                правила и хотспоты в styles.css (хвост файла), PNG 32×32 в
                assets/cursors/<key>.png (+_hover) — промты р.19, без файла —
                молча стандартный курсор; три режима в настройках: system /
                themed (по режимам) / fixed (один везде, тема в
                settings.cursorTheme); тест tests/cursors.test.mjs следит
                за синхронностью темы↔CSS
  tests/      — node --test; ui-smoke.test.mjs рендерит все экраны на DOM-стабе
  assets/     — только рантайм-картинки по тематическим папкам;
                исходники и PROMPTS.md — в ../art-src/ (пользователь генерирует сам)
  tools/      — sim-world.mjs (баланс), generate-assets.mjs (API-генерация),
                fate-deck.mjs (пересборка уровней и рук «Карт судьбы»)
```

## Архитектурные правила

- `core/` — чистая логика без DOM, вся проверяется тестами. `ui/` — только отображение
  и ввод. Данные — в `src/data/` объектами, новый контент = новые данные, не ветки кода.
- Состояние игры: `state.js` (newGame/migrate — миграции старых сейвов ТОЛЬКО там),
  localStorage ключ `cozy_adventures_save_v2`. Правки искалок из редактора —
  ОТДЕЛЬНЫЙ ключ `cozy_seek_overrides_v1` (не стирать, переживает новую игру).
- Все новые пользовательские строки — на русском. Есть регрессионные тесты на
  английские ключи (материалы, бонусы, тексты скиллов) — не ломать.

## Бой (src/core/formBattle.js + src/ui/formationView.js)

- Поле 8×3 клетки (24), союзники колонки 0–1, враги 6–7. Дальность: ближний бой — 1
  (соседи по Чебышёву), стрелки — 99, кастеры (skills из RANGED_SKILLS) — 2 и только
  при живом заслоне-не-кастере, иначе идут в упор. Манёвр стоит половину хода.
- Тактика Защита/Баланс/Нападение — `state.settings.tactic`; модификаторы союзников
  применяются снимком в simulateFormationBattle. В Защите ближнебойцы держат строй,
  только пока жив вражеский ближнебоец (иначе тупик по лимиту ходов).
- MAX_TICKS = 5000: тупик = поражение с `report.timedOut` и советом.
- Лог-события → реплей: start/hit/dodge/status/status_end/status_fail/sleeps/potion/
  scroll/move/dot. `move` и `dot` воспроизводятся ускоренно/мгновенно.
- `result.formation` — НАЧАЛЬНЫЕ клетки (снимок до прогона, не после!).
- Кастеры-капканы прошлого: не делай скилами врагов тег ranged — станут стационарной
  артиллерией и расстреляют заднюю линию (уже чинили). Дальность 2 + заслон.
- playBattleReplay — общий проигрыватель реплея (бой и Конструктор в Мастерской).

## Головоломки: механики (puzzleView.js — PUZZLE_TYPES + dispatch)

- mirror «Свет и фонарики»: `puzzle.js` + `solver.js`; тап по зеркалу, лучи, моль спит.
- shelf «Полки и товары»: `shelfPuzzle.js`; правила соседства.
- riddle «Загадки Хранителя»: `riddlePuzzle.js`; 100 уровней (bk_01–05, bk_106–200),
  одно слово ≤6 букв, расцветка попыток (на месте / есть / нет). Клавиатура ЙЦУКЕН
  с артом (общая с hang) + физическая клавиатура: кириллица — ход, латинские
  Z/H/R — команды (русские З/Р/К — это буквы ответа, им не назначать команд!).
  Е и Ё — одна клавиша (`canonLetter` во вводе, проверке и разметке); при
  победе `submitRiddle` возвращает в окошки исходное написание с Ё.
  Первый пакет погружения: тактильные клавиши, чернила и отдельные звуки,
  последовательный вердикт ДО `submitRiddle`, реплики кота, последняя попытка
  на листе + все черновики справа, золотая победа со звуками page/success/purr.
  Второй пакет: CSS-пергамент `riddle-sheet`, свеча/пыль на псевдоэлементах,
  перо `riddle-quill` позиционируется по окошку, вариативные KEEPER_REACTIONS,
  правила — `<details>` (раскрыты только на новом bk_01).
  Третий пакет: `data/riddleChapters.js` — 10 глав по 10 уровней, 5 тем,
  свои портрет/реплика и закладка; каждая десятая страница — сургучная печать.
- hang «Строки при свече»: `hangmanPuzzle.js`; 100 уровней (bk_06–bk_105) — стих
  классика (общественное достояние!) без последней строки, ответ А-ЯЁ + ✦ между
  словами, 8–24 буквы; свеча 6 ступеней. Промах −5% монет, догоревшая страница —
  дополнительно −10%, пол 30%; решение без ошибок ×1,5. `mistakes`/`spoiled`
  накопительные: отмена и сброс возвращают поле, но не откатывают цену ошибок.
  Вердикт применяется после паузы 260 мс; пергамент, чернила, реакции кота и
  золотая победа переиспользуют классы «Загадок». Тест следит за порядком уровней.
- seek «Поиск предметов»: `seekPuzzle.js` + редактор хотспотов (Мастерская).
- path/tea/mech/candle/flow «Тропинки»/«Чай»/«Механизмы»/«Свечи и духи»/«Потоки»:
  свои `*Puzzle.js`, решатели и уровни-данные `puzzles*.js`; тесты решают все уровни.
- brew «Варка зелий»: `brewPuzzle.js`; 100 уровней. Шаги crush/cut/drop — СНАЧАЛА кнопка
  инструмента («Ступка»/«Нож»/«Пипетка»), потом ингредиент (подсказка подсвечивает
  инструмент первым; в view — общий prepMode по PREP_TOOLS). Крышка — cover/uncover,
  состояние из истории (lidOn, как огонь). Шаг с `times` (1–5) — повторить действие
  N раз подряд; прогресс повторов — `state.reps`, отмена/сброс их учитывают.
  Механики дебютируют по главам без памяти: нож — brew_32, пипетка — brew_41,
  крышка — brew_51, повторы — brew_61 (тест следит). Режим памяти:
  `hideRecipe` + `peekSeconds`; хвост рецепта скрывается ЧАСТИЧНО — `brewHiddenCount`
  (по сложности: d3 — 2 последних, d4 — все кроме 4, d5 — все кроме 2; поле `hideTail`
  переопределяет). Отсчёт — в панели книги (без оверлея), «Заново» открывает книгу ещё раз.
  anyOf-шаги «ИЛИ» (times — только на шаге, не внутри anyOf). Валидатор проигрывает рецепт.
  Тесты также следят, что имена и рецепты всех 100 уровней уникальны.
  Уютный режим: `settings.keepBookOpen` (Настройки → Головоломки, плюс кнопка на
  экране варки уровней с памятью) — книга не закрывается, награды прежние.
  Вид зелья — `brewPotionLook(level, history)`: средний цвет ингредиентов
  (`color` в данных; `glow`/`sparkle` — свечение/блёстки). Микро-анимации
  действий — `playFx` + `.brew-fx` (styles.css); крышка на котле —
  `.brew-pot.covered` + пар; при порче зелье чернеет (`.brew-pot.spoiled`).
  Звуки действий — case'ы в `sound.js` (stir/crush/cut/drop/cover/uncover/
  heat/cool/wait/spoil, маппинг SFX_BY_DO в brewView); фоновое бульканье —
  `brewAmb` по setTimeout-цепочке в brewView, стоп при уходе с экрана.
  Заказчики — `data/brewGuests.js` (имя, icon, art из assets/fate или null →
  медальон-эмодзи; реплики idle/success/spoiled; BREW_LEVEL_GUESTS — привязка
  всех 100 уровней группами, тест следит). Благодарность — в оверлее победы,
  запись о варке — journalPush в дневник кота.
  Флакон-трофей — `ui/brewFlask.js` (6 SVG-силуэтов + тонировка, клип-маски
  с уникальными id); в оверлее победы — `art` в showOverlay + brewPotionLook
  по истории игрока, в «Книге рецептов» — brewFinalLook по полному рецепту.
- fate «Карты судьбы»: `fatePuzzle.js` + `puzzlesFate.js` + `tools/fate-deck.mjs`
  (см. «Контент» ниже). Драг на pointer events, превью карты в боковой панели,
  реплики гостя порциями, история раскладов — в панели справа с паучьим скроллом.
- glass «Витраж миров»: `glassPuzzle.js` + `puzzlesGlass.js`; пазл-перестановка
  сетки cols×rows, перемешка seeded-ГСЧ (гарантированно не собран на старте);
  арты `assets/glass/`, промты в `art-src/PROMPTS.md`.
- spin «Гобелены ветров»: `spinPuzzle.js` + `puzzlesSpin.js` + `spinView.js`;
  лоскуты стоят в своих клетках, но повёрнуты на 0/90/180/270°, тап крутит
  на 90° по часовой (плавная rAF-анимация с клипом в клетку). `rot[cell] ∈ 0..3`,
  эталон `parMoves` = Σ (4−rot)%4, медаль «Точная сборка» при moves ≤ par.
  100 уровней в 10 главах, сетки 2×2 → 8×5 (≤40 клеток — валидатор), звёзды
  сложности не убывают (тест следит), имена/интро/комбо image+grid уникальны.
  Арты переиспользованы из assets/ (glass, battle, seek, hub, tea, brew, fate);
  повтор картинки — только с другой раскройкой. Дебюты: якоря `anchors`
  (📌, не крутятся) — sp_05; «слепые» уровни `goldRim: false` — sp_09;
  8×5 — sp_62. Подсказка — первый неверный лоскут + стрелка ↻; цепочка
  решает (тест следит).
- gift «Подарок для гостя»: `giftPuzzle.js` + `puzzlesGift.js` (SOUVENIRS —
  66 сувениров с русскими тегами + 100 уровней: гость из «Карт судьбы»,
  история с зашитыми need/avoid-условиями, витрина 6–9, ровно один
  подходящий — следит валидатор). 3 попытки, награда 100/75/50%, третья
  неудача — гость уходит, `restartGift` без штрафа; намёк = первое
  нарушенное условие (avoid раньше need). Подсказка прячет обманку,
  ближайшую к ответу по тегам. Арт `assets/gift/` (gift_counter + souv_*),
  промты р.20 PROMPTS.md, фолбэки — эмодзи. В STORY_RING 15-м типом.
- seating «Гости за чайным столом»: `seatingPuzzle.js` + `seatingGuests.js` +
  `puzzlesSeating.js`; 100 уровней seat_01–seat_100 (10 глав, детерминированный
  генератор + решатель: решение ровно одно, следит seating.test.mjs). Комната —
  монолитный арт `assets/seating/seat_chXX_web.jpg`, поверх только полупрозрачные
  зоны мест и кружки портретов (без постоянных DOM/SVG-спрайтов); стулья различаются
  положением и цветом подушечек, но пожелания звучат как симпатии/причины
  («любит фиалки», «замёрз и хочет погреться»), цвет — крайний признак для
  визуально спорных мест; нераспределённые
  гости — карточки на подносе под сценой (портрет из GUEST_BY_ID, черты, пожелания),
  посаженный гость превращает карточку в пустое гнездо. Драг на pointer events +
  тапы (карточка выбирает, место сажает, кружок поднимает), превью гостя/места в
  боковой панели по образцу «Карт судьбы». «Подать чай» без штрафов и таймера:
  первое нарушение или «осталось посадить N». Подсказка реально выполняет
  place/move/remove из единственного решения. В STORY_RING 16-м типом.
- Оверлеи победы: Enter/Пробел нажимает основную кнопку («Следующая →») —
  `showOverlay` в `common.js` + локальный `showVictory` в `puzzleView.js`.

## Режим истории (story)

- Движок `core/storyEngine.js` (чистая логика, тесты `tests/story.test.mjs`), контент —
  `data/story.js`: STORY_RING (кольцо 16 типов), STORY_GUESTS (круг из 35 гостей;
  keeper и spirit НЕ в круге), STORY_PROLOG, STORY_BEATS (37/74/100 — дух),
  STORY_CAT_BEATS (кот каждые 10 шагов: `step % 10 === 8`), STORY_EPILOG, TASK_LINES
  (2 фразы-задания на тип), GUEST_SCRIPT (voice + visits[1..3 и «свой человек»] +
  praise с плейсхолдером `{дело}` + silence).
- Порядок головоломок НЕ хардкодится: тип = кольцо от `story.step`, уровень — первый
  нерешённый цепочки типа; пустые типы пропускаются, каталог-прогресс учитывается.
- Хотспот-гость в лавке (`STORY_GUEST_SPOT` в hub.js) → маршрут `story`
  (`ui/storyView.js`): крупный портрет, реплики по тапу, «К делу» → головоломка.
- Память: `story.guests[id] = { visits, lastPuzzle, silenceShown }`; praise помнит
  прошлое задание; подкол про молчание — один раз на гостя (визит 2 или 3,
  детерминированно от id). Хозяин никогда не отвечает — это фишка.
- `storyOnPuzzleComplete` вызывается из completePuzzle И skipPuzzle (пропуск тоже
  закрывает задание). `story.justCompleted` → кнопка «📖 Дальше по истории» в
  showOverlay (common.js) и showVictory (puzzleView.js), сбрасывается при показе.
- Выкл: Настройки → Головоломки → «Режим истории» (`settings.storyMode`, default true).
- Новый гость истории = id в STORY_GUESTS + блок в GUEST_SCRIPT; гость обязан быть в
  GUESTS гостевой книги; все строки — без латиницы (тест следит).

## Гостевая книга

- Хотспот «Гостевая книга» в сцене лавки → маршрут `guests` → `ui/guestBookView.js`.
- `data/guests.js` объединяет повторных гостей `puzzlesFate.js` и заказчиков
  `brewGuests.js`; описания и реплики для диалогов хранятся там же. Новый гость =
  существующий портрет/эмодзи + минимум две русские темы `{ ask, answer }`.
- Четыре вида списка (полка, портрет, список, мозаика) сохраняются в
  `settings.guestCatalogMode`; профиль с разговором листается без закрытия окна.

## Контент: как добавлять

- Загадка: данные в `src/data/puzzles*.js` (новая механика = core + view + routing в
  `puzzleView.js` + id в `CAMPAIGN_ORDER` в `state.js` + тесты + строка в ui-smoke).
- Предмет: `items.js` + `shop.js` SHOP_STOCK (unlockAfter) + тип в SHOPS лавки
  (тип 'scroll' → лавка Мага, 'potion' → Алхимик); сеты — `sets.js`. Иконка:
  `assets/items/<id>_web.jpg` поверх эмодзи (`itemIconEl` в `ui/itemTip.js`,
  фолбэк сам), промты и фоны по редкости — `art-src/PROMPTS.md`, р.18.
- Бой/враг: `enemies.js` (или `data/worlds/*.js`) + `battles.js`.
- Искалка: `puzzlesSeek.js`; координаты точек правятся через встроенный редактор
  (Мастерская → Редактор искалок), экспорт JSON → вшить в данные.
- Карты судьбы: `puzzlesFate.js` (FATE_CARDS — колода; уровень = гость + история
  из 3–4 реплик с `accept`-картами + перемешанная рука с обманками). Гости
  ПОВТОРЯЮТСЯ: новый уровень = новая история старого знакомого, новые портреты
  не генерируем. Колода растёт по ОДНОЙ новой карте за дебютный уровень (тест
  следит); филлер-уровни без новых карт допустимы — генератор ставит их
  промежуточно. Порядок уровней и руки пересобирает `node tools/fate-deck.mjs`
  (спека историй в нём, вход — puzzlesFate.js; не идемпотентен: после прогона
  вход восстановить из git), затем `npm run build && npm test`. Промпты карт —
  `art-src/PROMPTS.md`, р.16.
- Витраж миров: `puzzlesGlass.js` (уровень = `grid: [cols, rows]` + `image` +
  награды; арты `assets/glass/`, промты в `art-src/PROMPTS.md`).
- Питомцы/спутники на сценах: `PET_SPOTS`/`CREW_SPOTS` в `hub.js`.

## Известные грабли (не наступай повторно)

- **`hub.js` правит сам пользователь** (координаты хотспотов, питомцев, внешек):
  перед правкой файла читай его заново и сохраняй его цифры.
- Pillow: маска из numpy в `Image.fromarray()` readonly → `.copy()`, иначе floodfill
  молча не работает. Ресайз RGBA — только с премультиплицированной альфой (иначе
  цветной ореол). Модели рисуют «прозрачный фон» как шахматку — просить
  `plain solid white background` и вырезать скриптом (маска «яркий и почти серый» +
  заливка от краёв; карманы фона между прядями — разрастанием маски).
- Тест-стаб DOM в ui-smoke не имеет `createTextNode` — только элементы.
  И `requestAnimationFrame` там тоже нет: в ui-коде — фолбэк на прямой вызов.
- Глоб в `npm test` требует Node ≥ 22.
- SW (sw.js): код — network-first, ассеты — cache-first. Меняешь кэширование —
  подними версию CACHE.
- Пользователь генерирует ассеты сам по `art-src/PROMPTS.md`; большие оригиналы
  (jfif/png) хранятся в `art-src/<тема>/`, в рантайм идут сжатые `*_web.jpg` / `*.webp`
  из тематических папок `game/assets/`.

## Git и секреты

- Коммит/пуш — ТОЛЬКО по явной просьбе пользователя («коммит/пуш»). Без просьбы — нет.
- `.env` (ключи cleanapis API) НИКОГДА не коммитим и не читаем вслух; в .gitignore.
  Перед коммитом: `git add -A && git diff --cached --name-only | grep -icE "^\.env$|node_modules|\.venv"` должно дать 0.
- После пуша деплой идёт сам; проверка: GitHub API `/actions/runs` (публично).
