# AGENTS.md — инструкция для агентов

Проект: **«Лавка на перекрёстке миров»** — уютная браузерная игра (хозяин волшебной
лавки: головоломки, обустройство, найм команды, автобои рыцаря). Весь код на русском,
все пользовательские тексты СТРОГО по-русски. Дизайн-документ: `Второй анализ после
ответов.txt` в корне. План/история: `PLAN.md`, `game/README.md` (местами устарели —
истина в коде и тестах).

## Стек и запуск

- Чистый JavaScript (ES-модули) + Canvas 2D + DOM. **Ноль зависимостей в продакшене**;
  esbuild — только чтобы собрать `game/bundle.js`.
- Запуск игры: двойной клик `game/index.html` (работает с file://) или
  `npm run serve` в `game/`.
- **Команды (cwd = `game/`):**
  - `npm run build` — собрать бандл. **ОБЯЗАТЕЛЬНО после любой правки `src/`**:
    игра грузит `bundle.js`, не исходники.
  - `npm test` — `node --test "tests/*.test.mjs"`. После правок всегда
    `npm run build && npm test`.
  - `node tools/sim-world.mjs <worldId> 40` — баланс мира (винрейт эндгейм-билдом).
    Миры: nm, sw, sf, ash, cr, jade, deep, mist.
- CI (GitHub Actions, `.github/workflows/deploy.yml`): пуш в main → тесты → сборка →
  деплой на GitHub Pages (https://k8rvin.github.io/CozyAdventures/). Node 22
  (test-runner с glob не работает на Node 20 — не понижать).

## Структура

```
game/
  index.html, styles.css, bundle.js (собранный), manifest.webmanifest, sw.js (PWA/офлайн)
  src/core/   — чистая логика БЕЗ DOM (state.js, formBattle.js, *Puzzle.js, items.js, rng.js)
  src/data/   — контент как данные (items, enemies, battles, puzzles*, crew, shop, sets…)
  src/ui/     — экраны (app.js — роутер и ctx; hub.js — сцены-хабы; *View.js)
  tests/      — node --test; ui-smoke.test.mjs рендерит все экраны на DOM-стабе
  assets/     — картинки; PROMPTS.md — промты для генерации (пользователь генерирует сам)
  tools/      — sim-world.mjs (баланс), generate-assets.mjs (API-генерация)
```

## Архитектурные правила

- `core/` — чистая логика без DOM, вся проверяется тестами. `ui/` — только отображение
  и ввод. Данные — в `src/data/` объектами, новый контент = новые данные, не ветки кода.
- Состояние игры: `state.js` (newGame/migrate — миграции старых сейвов ТОЛЬКО там),
  localStorage ключ `cozy_adventures_save_v2`. Правки искалок из редактора —
  ОТДЕЛЬНЫЙ ключ `cozy_seek_overrides_v1` (не стирать, переживает новую игру).
- Все новые пользовательские строки — на русском. Есть регрессионные тесты на
  английские ключи (материалы, бонусы, тексты скиллов) — не ломать.

## Бой (src/core/formBattle.js + src/ui/formationView.js)

- Поле 8×3 клетки (24), союзники колонки 0–1, враги 6–7. Дальность: ближний бой — 1
  (соседи по Чебышёву), стрелки — 99, кастеры (skills из RANGED_SKILLS) — 2 и только
  при живом заслоне-не-кастере, иначе идут в упор. Манёвр стоит половину хода.
- Тактика Защита/Баланс/Нападение — `state.settings.tactic`; модификаторы союзников
  применяются снимком в simulateFormationBattle. В Защите ближнебойцы держат строй,
  только пока жив вражеский ближнебоец (иначе тупик по лимиту ходов).
- MAX_TICKS = 5000: тупик = поражение с `report.timedOut` и советом.
- Лог-события → реплей: start/hit/dodge/status/status_end/status_fail/sleeps/potion/
  scroll/move/dot. `move` и `dot` воспроизводятся ускоренно/мгновенно.
- `result.formation` — НАЧАЛЬНЫЕ клетки (снимок до прогона, не после!).
- Кастеры-капканы прошлого: не делай скилами врагов тег ranged — станут стационарной
  артиллерией и расстреляют заднюю линию (уже чинили). Дальность 2 + заслон.
- playBattleReplay — общий проигрыватель реплея (бой и Конструктор в Мастерской).

## Контент: как добавлять

- Загадка: данные в `src/data/puzzles*.js` (новая механика = core + view + routing в
  `puzzleView.js` + id в `CAMPAIGN_ORDER` в `state.js` + тесты + строка в ui-smoke).
- Предмет: `items.js` + `shop.js` SHOP_STOCK (unlockAfter) + тип в SHOPS лавки
  (тип 'scroll' → лавка Мага, 'potion' → Алхимик); сеты — `sets.js`.
- Бой/враг: `enemies.js` (или `data/worlds/*.js`) + `battles.js`.
- Искалка: `puzzlesSeek.js`; координаты точек правятся через встроенный редактор
  (Мастерская → Редактор искалок), экспорт JSON → вшить в данные.
- Питомцы/спутники на сценах: `PET_SPOTS`/`CREW_SPOTS` в `hub.js`.

## Известные грабли (не наступай повторно)

- **`hub.js` правит сам пользователь** (координаты хотспотов, питомцев, внешек):
  перед правкой файла читай его заново и сохраняй его цифры.
- Pillow: маска из numpy в `Image.fromarray()` readonly → `.copy()`, иначе floodfill
  молча не работает. Ресайз RGBA — только с премультиплицированной альфой (иначе
  цветной ореол). Модели рисуют «прозрачный фон» как шахматку — просить
  `plain solid white background` и вырезать скриптом (маска «яркий и почти серый» +
  заливка от краёв; карманы фона между прядями — разрастанием маски).
- Тест-стаб DOM в ui-smoke не имеет `createTextNode` — только элементы.
- Глоб в `npm test` требует Node ≥ 22.
- SW (sw.js): код — network-first, ассеты — cache-first. Меняешь кэширование —
  подними версию CACHE.
- Пользователь генерирует ассеты сам по `assets/PROMPTS.md`; большие оригиналы
  (jfif/png) — исходники, в рантайм идут сжатые `*_web.jpg` / `*.webp`.

## Git и секреты

- Коммит/пуш — ТОЛЬКО по явной просьбе пользователя («коммит/пуш»). Без просьбы — нет.
- `.env` (ключи cleanapis API) НИКОГДА не коммитим и не читаем вслух; в .gitignore.
  Перед коммитом: `git add -A && git diff --cached --name-only | grep -icE "^\.env$|node_modules|\.venv"` должно дать 0.
- После пуша деплой идёт сам; проверка: GitHub API `/actions/runs` (публично).

## Быстрая проверка работы

1. `cd game && npm run build && npm test` — все тесты зелёные.
2. Открыть `game/index.html`, Ctrl+F5.
3. Читы для ручной проверки (5 тапов по версии в настройках): КОТОПЁС, ЗОЛОТАЯЛАВКА,
   ПЕЧАЛЬ, КОЛДОВСТВО, РЫЦАРЬ, ОБУЧЕНИЕ, ПАУЧОК.
