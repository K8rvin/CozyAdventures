# AGENTS.md — инструкция для агентов

Проект: **«Лавка на перекрёстке миров»** — уютная браузерная игра (хозяин волшебной
лавки: головоломки, обустройство, найм команды, автобои рыцаря). Весь код на русском,
все пользовательские тексты СТРОГО по-русски. Дизайн-документ: `Второй анализ после
ответов.txt` в корне. План/история: `PLAN.md`; игрокам и разработчикам — актуальный
обзор `game/README.md`. При расхождении истина в коде и тестах.

## Стек и запуск

- Чистый JavaScript (ES-модули) + Canvas 2D + DOM. **Ноль зависимостей в продакшене**;
  esbuild — только чтобы собрать `game/bundle.js`.
- Запуск игры: двойной клик `game/index.html` (работает с file://) или
  `npm run serve` в `game/`.
- **Команды (cwd = `game/`):**
  - `npm run build` — собрать бандл. **ОБЯЗАТЕЛЬНО после любой правки `src/`**:
    игра грузит `bundle.js`, не исходники.
  - `npm test` — `node --test "tests/*.test.mjs"`. После правок всегда
    `npm run build && npm test`.
  - `node tools/sim-world.mjs <worldId> [minWinrate] [profile]` — винрейт мира;
    по умолчанию порог 60 и профиль `endgame`. Профили: `endgame` (готовый
    эндгейм-билд), `available` (верхняя граница открытого снаряжения, не путь
    игрока), `reasonable` (консервативные покупки на первые монетные награды),
    `upgrade` (reasonable + одно следующее усиление), `all` (все четыре).
    Миры: meadow, town, attic, crossroads, nm, sw, sf, cr, ash, jade, deep, mist.
  - `node tools/sim-economy.mjs all` — все нормативные сценарии дохода и покупок;
    `node tools/sim-economy.mjs shopping` — только бюджет и разовые стоки.
- CI (GitHub Actions, `.github/workflows/deploy.yml`): пуш в main → тесты → сборка →
  деплой на GitHub Pages (https://k8rvin.github.io/CozyAdventures/). Node 22
  (test-runner с glob не работает на Node 20 — не понижать).

## Архитектурные правила

- `core/` — чистая логика без DOM, вся проверяется тестами. `ui/` — только отображение
  и ввод. Данные — в `src/data/` объектами, новый контент = новые данные, не ветки кода.
- Состояние игры: `state.js` (newGame/migrate — миграции старых сейвов ТОЛЬКО там),
  localStorage ключ `cozy_adventures_save_v2`. Правки искалок из редактора —
  ОТДЕЛЬНЫЙ ключ `cozy_seek_overrides_v1` (не стирать, переживает новую игру).
- Все новые пользовательские строки — на русском. Есть регрессионные тесты на
  английские ключи (материалы, бонусы, тексты скиллов) — не ломать.

## Первая дуга и цели

- Дуга: `core/onboarding.js` + `data/onboarding.js` + `ui/onboardingView.js`.
  Статусы `active/paused/skipped/done`; restart и миграции не выдают прогресс заново.
- Маршрут: `prologOnly` → md_01 → md_02 → выбор tw_01 / sk_md_01 / pp_01 →
  bt_slimes → площадь и торговый квартал → bt_path → честные bt_bees. Первая
  неудача включает safe-пояс; далее rng_health + пояс, честный повтор,
  rcp_pot_heal и финал. CTA ТОЛЬКО маршрутизирует, не отмечает действие сделанным.
- Необязательный guide после финала ведёт по 8 разделам; на старых сейвах сам не
  запускается. Цель накопления `core/goals.js`: item/crew/recipe, карточка в hub,
  кнопки в магазинах/таверне/кузнице и прогресс в оверлеях наград.

## Экономика

- `core/economy.js` + `data/economy.js`: `expectedFirst/RepeatSeconds` — нормативный
  объём контента, НЕ таймер игрока. Ярусы 0..5, скорость `v = 20 + 4t` монет/мин;
  `derivePuzzleCatalog/derivePuzzle` формирует rewards для ALL_PUZZLES по tier/order/
  finale. Повтор головоломки ≈25%, боя ≈20%. Печати — только финалы 16 типов и
  первые победы над боссами. Daily ×2 работает и после кампании; пропуск честно
  отличается от честного решения. `economyVersion` фиксирует модель без пересчёта
  старых денег; фактические и отчётные награды обязаны совпадать.
- Покупка/продажа использует эффективную цену `pricedShopItem` (tier/order/override),
  НЕ сырой `ITEM_BY_ID.price`. Не обходить этот слой в UI, симуляциях и целях.
- `sim-economy.mjs`: доход 76 762 монеты, разовые стоки 55 320 (косметика
  1 310), отношение ≈1,39. Печатные стоки 45, печати 62/45 ≈1,38. Это измерение
  модели на текущий контент, не обещание игроку и не фактический темп прохождения.
- `sim-world` по умолчанию использует endgame. Текущий nm_17: scales 1,64,
  endgame 42%, reasonable 71%, upgrade 100%; остальные endgame-миры выше 40%.
  Новые большие сборы проходят пороги tests/battleCrowds.test.mjs. Прежние
  nm_06/nm_07/nm_08/nm_boss теперь 100/100/100/96% по reasonable, но баланс не
  идеален: остаются sf_boss 0%, cr_10 38%, cr_15/cr_16 0% и старые провалы
  ранних миров. Это слабости конкретного профиля, не всех билдов.

## Энергия и босс-находки

- `core/energy.js` + `data/energy.js`: cap 36, +1 каждые 2 часа. Первое прохождение
  и поражение бесплатны; наградный repeat стоит 1, босс 3 после победы. Нехватка —
  честный `blocked`. Practice не даёт наград, прогресса, pity и не меняет пояс/сейв.
- `core/bossDrops.js` + `data/bossDrops.js`: 12 внесетовых rare предметов, шанс
  5% +2 п.п. за сухую наградную победу, гарантия на 12-й, itemFind ограничен +5 п.п.
  Отдельные RNG, pity и anti-dup; дроп не входит в магазин или рецепты сам по себе.

## Хаб и косметика

- `core/hubGeometry.js` + `LAVKA_HOTSPOT_SHAPES`: 7 полигонов лавки, native buttons
  + clip-path, bbox-fallback, labels/dots вне обрезки, mobile nav и доступные
  спрайты. Старой lens и дополнительной intro-заставки нет. Сцена 3:1, reduced-motion.
- V2 уже интегрированы и проверены в Chrome: `town_square_v2_web.jpg`,
  `town_market_v2_web.jpg`, `trophy_room_v2_web.jpg` (2400×800) с layoutId
  `square_v2_3x1` / `market_v2_3x1` / `cabinet_v2_3x1`. У них свои полигоны и
  12+4 места кабинета; error возвращает старый файл и legacy circles/центры.
  Координаты не перезаписывать без новой визуальной разметки.
- `COSMETIC_PACKS`: шесть pack id, `COSMETICS_VERSION=2`, aliases старых покупок
  (carpet+crest → hearth и т.д.) без повторной оплаты. Один активный pack;
  resolver выбирает variant по `scenes[scene]`, scene-specific base и `src + layoutId`.
  Все шесть `lavka_pack_<id>_web.jpg` уже в runtime (2400×800). У каждого свой
  `lavka_pack_<id>_3x1` в `LAVKA_COSMETIC_LAYOUTS` (`data/cosmetics.js`): 7 полигонов
  и места pet_puppy/cmp_cat/cmp_firefly/story_guest по фактическому арту. Реестр
  `LAVKA_LAYOUTS` в hub.js использует `mergeSceneLayout`, не меняя базовые координаты.
  Pending/missing/unknown layout → база + прежние overlays и базовая геометрия;
  successful load → pack layout, legacy-слой скрывается. В Chrome проверены все
  42 маршрута, клавиатура, 390 px/touch и обе ветки загрузки.
- Будущие темы сначала получают промт и реальные файлы, затем проходят приёмку.
  Не добавлять их в данные или магазин заранее. Актуальные промты — р.22.

## Бой (src/core/formBattle.js + src/ui/formationView.js)

- Поле 8×3 клетки (24), союзники колонки 0–1, враги 6–7. Дальность: ближний бой — 1
  (соседи по Чебышёву), стрелки — 99, кастеры (skills из RANGED_SKILLS) — 2 и только
  при живом заслоне-не-кастере, иначе идут в упор. Манёвр стоит половину хода.
- Тактика Защита/Баланс/Нападение — `state.settings.tactic`; модификаторы союзников
  применяются снимком в simulateFormationBattle. В Защите ближнебойцы держат строй,
  только пока жив вражеский ближнебоец (иначе тупик по лимиту ходов).
- MAX_TICKS = 5000: тупик = поражение с `report.timedOut` и советом.
- Лог-события → реплей: start/hit/dodge/status/status_end/status_fail/sleeps/potion/
  scroll/move/dot. `move` и `dot` воспроизводятся ускоренно/мгновенно.
- `result.formation` — НАЧАЛЬНЫЕ клетки (снимок до прогона, не после!).
- Кастеры-капканы прошлого: не делай скилами врагов тег ranged — станут стационарной
  артиллерией и расстреляют заднюю линию (уже чинили). Дальность 2 + заслон.
- Боссы (`boss: true` в данных, 12 шт) — блок 2×2: `unit.size`, якорь `unit.cell` =
  левая верхняя клетка, `unitCells`/`unitDist` вместо точечного cellDist. Авторасстановка
  клеточная: босс первым якорем [6,0], прислужников ≤2 (свободны лишь 2 клетки —
  следит тест). В UI — `.unit-figure.big`/`.form-slot.boss`, центр = якорь +
  (6.25%, 16%); снимок `result.formation` хранит `size`.
- playBattleReplay — общий проигрыватель реплея (бой и Конструктор в Мастерской).
- Арт рыцаря в бою зависит от оружия: `knightArtId(equipped)` в core/items.js →
  knight / knight_twohanded / knight_bow / knight_staff; unitSpriteEl с
  fallbackArt откатывается на базовый набор, пока файлов нет. Промты наборов —
  art-src/PROMPTS_BATTLE.md, секции 78–80 (следит battleArt.test.mjs, счёт 80).

## Комната рыцаря: генерация цельного портрета через Gemini

- Активный режим — НЕ layered: `ui/knightGeneratedView.js` получает один цельный
  WebP по комплекту экипировки. Старые `knightDollView`, Canvas, принятые броня/
  меч/щит/зелье и production-manifest изолированных предметов в UI НЕ используются
  и не служат fallback. `core/knightDoll.js` остаётся только для русского описания.
  Боевая `knightArtId` — отдельная система и не затрагивается.
- `core/knightImagePrompt.js` валидирует состояние, строит стабильный ключ комплекта
  и prompt. `data/knightVisuals.js` — все 122 английских описания, генерируется из
  `art-src/PROMPTS_KNIGHT.md` командой `node tools/build-knight-visuals.mjs`.
  Референсы: тело `doll/<bodyId>/full.png`, `room_no_mirrors.png` и иконки; максимум 13.
  `KNIGHT_IMAGE_PROMPT_VERSION=5` входит и в IndexedDB key, и в backend hash, поэтому
  смена prompt не подставляет старое изображение. Одноручное оружие обязано быть
  в правой кисти, щит — на левом предплечье, никакого оружия на полу; зеркала
  и отражающие поверхности запрещены. Двуручное скрывает щит, оба кольца/расходника
  входят в prompt, повтор ID не увеличивает число файлов.
  `settings.knightBody` меняет ключ, невалидное тело → male.
- `tools/knight-server.mjs` (Node 22, без JS-зависимостей): static + `/health` +
  POST `/api/knight-image` + GET `/api/knight-cache/<sha256>.webp`. Провайдеры:
  Gemini REST `v1beta/interactions` (`gemini-nano-banana-2.1`) и OpenRouter
  `api/v1/chat/completions` (`google/gemini-3.1-flash-image`, `modalities: image+text`,
  `image_url`, `image_config` 4:5 1K). Выбор — `KNIGHT_IMAGE_PROVIDER`, при наличии
  `OPENROUTER_API_KEY` он выбирается автоматически; модель можно переопределить
  `OPENROUTER_IMAGE_MODEL`/`GEMINI_IMAGE_MODEL`. Ключи только backend `.env`/Render,
  НЕ в браузере/логах. Валидация, CORS,
  rate limit, очередь 2, timeout/retry, in-flight coalescing.
- `tools/convert-knight-image.py` (Pillow): WebP 768×960, quality 86, atomic WebP+JSON
  metadata. Локально `game/.cache/knight` (в .gitignore), на Render `KNIGHT_CACHE_DIR`
  на persistent disk, TTL нет. Повторный комплект НИКОГДА не генерируется заново;
  после перезапуска читается готовый WebP. Dockerfile ставит Node 22 + Python/Pillow.
- Постоянство также в IndexedDB `knight_portraits_v1`: после успеха Blob сохраняется
  по каноническому key. При rerender сначала memory/IndexedDB/backend, только cache
  miss → Gemini. Фильтры и hover новый запрос не создают. Debounce 400 мс, последний
  комплект wins, destroy отменяет fetch и запрещает поздний ответ.
- Во время генерации допустимо последнее СГЕНЕРИРОВАННОЕ изображение + status;
  иначе нейтральная рамка. При ошибке сохраняется последний generated image/нейтральный
  статус, не старые слои. `game/knight-api.js` содержит только публичный URL/endpoint,
  сейчас локальный `/api/knight-image`; пустая строка отключает сетевые запросы.
- Тесты: `knightImagePrompt.test.mjs`, `knightServer.test.mjs` (test mode + WebP +
  persistent cache), `knightGeneratedView.test.mjs` (IndexedDB/lifecycle) и generated
  ветка `ui-smoke.test.mjs`. Платный Gemini в `npm test` не вызывается;
  `KNIGHT_TEST_MODE=1 node tools/knight-server.mjs` — локальный end-to-end.
  После правок `src/` обязательны `npm run build && npm test`. Публичный deploy на
  Render и включение URL — только после живой визуальной приёмки и явного разрешения.

## Головоломки: механики (puzzleView.js — PUZZLE_TYPES + dispatch)

- shelf «Полки и товары»: `shelfPuzzle.js`; правила соседства.
- riddle «Загадки Хранителя»: `riddlePuzzle.js`; 100 уровней (bk_01–05, bk_106–200),
  одно слово ≤6 букв, расцветка попыток (на месте / есть / нет). Клавиатура ЙЦУКЕН
  с артом (общая с hang) + физическая клавиатура: кириллица — ход, латинские
  Z/H/R — команды (русские З/Р/К — это буквы ответа, им не назначать команд!).
  Е и Ё — одна клавиша (`canonLetter` во вводе, проверке и разметке); при
  победе `submitRiddle` возвращает в окошки исходное написание с Ё.
  Первый пакет погружения: тактильные клавиши, чернила и отдельные звуки,
  последовательный вердикт ДО `submitRiddle`, реплики кота, последняя попытка
  на листе + все черновики справа, золотая победа со звуками page/success/purr.
  Второй пакет: CSS-пергамент `riddle-sheet`, свеча/пыль на псевдоэлементах,
  перо `riddle-quill` позиционируется по окошку, вариативные KEEPER_REACTIONS,
  правила — `<details>` (раскрыты только на новом bk_01).
  Третий пакет: `data/riddleChapters.js` — 10 глав по 10 уровней, 5 тем,
  свои портрет/реплика и закладка; каждая десятая страница — сургучная печать.
- hang «Строки при свече»: `hangmanPuzzle.js`; 100 уровней (bk_06–bk_105) — стих
  классика (общественное достояние!) без последней строки, ответ А-ЯЁ + ✦ между
  словами, 8–24 буквы; свеча 6 ступеней. Промах −5% монет, догоревшая страница —
  дополнительно −10%, пол 30%; решение без ошибок ×1,5. `mistakes`/`spoiled`
  накопительные: отмена и сброс возвращают поле, но не откатывают цену ошибок.
  Вердикт применяется после паузы 260 мс; пергамент, чернила, реакции кота и
  золотая победа переиспользуют классы «Загадок». Тест следит за порядком уровней.
- seek «Поиск предметов»: `seekPuzzle.js` + редактор хотспотов (Мастерская).
- path/tea/mech/candle/flow «Тропинки»/«Чай»/«Механизмы»/«Свечи и духи»/«Потоки»:
  свои `*Puzzle.js`, решатели и уровни-данные `puzzles*.js`; тесты решают все уровни.
- brew «Варка зелий»: `brewPuzzle.js`; 100 уровней. Шаги crush/cut/drop — СНАЧАЛА кнопка
  инструмента («Ступка»/«Нож»/«Пипетка»), потом ингредиент (подсказка подсвечивает
  инструмент первым; в view — общий prepMode по PREP_TOOLS). Крышка — cover/uncover,
  состояние из истории (lidOn, как огонь). Шаг с `times` (1–5) — повторить действие

- Движок `core/storyEngine.js` (чистая логика, тесты `tests/story.test.mjs`), контент —

## Известные грабли (не наступай повторно)

- **`hub.js` правит сам пользователь** (координаты хотспотов, питомцев, внешек):
  перед правкой файла читай его заново и сохраняй его цифры. Текущие силуэты —
  `LAVKA_HOTSPOT_SHAPES`, не исторические координаты из PROMPTS.
- Монетные rewards и печати — derived-слой `core/economy.js`: не добавляй вторую
  ручную таблицу поверх него. Цены только через `pricedShopItem`; expectedSeconds —
  норматив модели, не обещанное время игрока.
- Practice не должен начислять монеты, материалы, прогресс или pity и не меняет
  пояс/сейв; наградный repeat без энергии заканчивается blocked до симуляции.
- Lifecycle: tutorial — singleton с destroy; реплей и его таймеры/оверлеи требуют
  cleanup при уходе. Достижения учитывают уникальные честные уровни, не повторы и
  пропуски; награда в отчёте не должна расходиться с фактической.
- Миграции только в `state.js` и идемпотентны. Не затирай `legacyCosmeticsActive`:
  он нужен до загрузки полного фона, после load legacy-слой скрывается.
- Pillow: маска из numpy в `Image.fromarray()` readonly → `.copy()`, иначе floodfill
  молча не работает. Ресайз RGBA — только с премультиплицированной альфой (иначе
  цветной ореол). Модели рисуют «прозрачный фон» как шахматку — просить
  `plain solid white background` и вырезать скриптом (маска «яркий и почти серый» +
  заливка от краёв; карманы фона между прядями — разрастанием маски).
- Тест-стаб DOM в ui-smoke не имеет `createTextNode` — только элементы.
  И `requestAnimationFrame` там тоже нет: в ui-коде — фолбэк на прямой вызов.
- Глоб в `npm test` требует Node ≥ 22.
- SW (sw.js): код — network-first, ассеты — cache-first. Меняешь кэширование —
  подними версию CACHE.
- Пользователь генерирует ассеты сам по `art-src/PROMPTS.md`; большие оригиналы
  (jfif/png) хранятся в `art-src/<тема>/`, в рантайм идут сжатые `*_web.jpg` / `*.webp`
  из тематических папок `game/assets/`. V2 и шесть полных `lavka_pack` уже есть;
  не выдавай metadata/prompt за готовый файл и не убирай прежний fallback.
